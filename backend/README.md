# Backend source code

هذا المجلد هو المصدر المعتمد لتعديل باك إند CUT-HUB-POS. التقسيم يحافظ على الكود وأسماء الدوال وترتيب التهيئة كما كانت قبل إعادة التنظيم.

## أين تعدّل؟

| المجلد | المسؤولية |
| --- | --- |
| `core` | إعداد البيئة والراوتر `doPost` وإخراج JSON |
| `auth` | المستخدمون والصلاحيات والجلسات والتشفير وترحيل كلمات المرور وتقييد محاولات الدخول |
| `shared` | التواريخ والأرقام وفحص أعمدة الشيتات |
| `audit` | سجل الأنشطة |
| `catalog` | الخدمات والأسعار |
| `inventory` | الأصناف والمشتريات والوصفات والمخزون وخطة الخصم والتراجع عن المعاملة |
| `staff` | بيانات الموظفين وعقود الشيتات ومحرك الحضور الأساسي |
| `scheduling` | محرك الجداول وتكامله مع Apps Script |
| `attendance` | الحضور القديم والمحرك الحالي وتكامله مع Apps Script |
| `payroll` | محرك احتساب الحضور للرواتب وتكامله مع Apps Script |
| `accounting` | المصروفات والسحوبات والإقفال اليومي والشهري |
| `invoices` | أعمدة الفواتير والإنشاء والتعديل والاستعلام والحذف وPDF |
| `reports` | تقارير المبيعات والعملاء |
| `booking` | الحجوزات العامة والداخلية والتقييمات والتوافق مع التنفيذ القديم |
| `availability` | محرك الإتاحة والتقييم والمعاملات والنسخ والتعارضات والفروع وكاشف عدم الحضور |
| `staging` | أدوات المعاينة والتهيئة والترحيل الموجودة بالفعل في الحزمة |

هناك 81 ملف JavaScript. الوحدات التي كانت مستقلة أصلًا، ومنها محركات الحضور والجداول والرواتب، احتفظت بحدودها وواجهاتها. ملفات `legacy` ما زالت مستخدمة بواسطة مسارات التوافق الحالية.

## التعديل والتحقق

1. عدّل الملف المناسب هنا. الدوال التي تشترك في نطاق Apps Script العام تظل عامة؛ لا تضف `import` أو `export` أو تغليفًا جديدًا للدوال.
2. شغّل من جذر المشروع:

   ```sh
   node scripts/build-backend.js
   node scripts/validate-apps-script-deployment-package.js
   node --test tests/*.test.js
   ```

3. أضف المصادر وتغييرات الملفات المولدة معًا إلى مراجعة التعديل.

لفحص التزامن دون كتابة ملفات:

```sh
node scripts/build-backend.js --check
```

الترتيب المعتمد موجود في `config/backend-sources.json`. لا تغيّر ترتيب الوحدات لمجرد تجميع أسماء المجلدات: بعض الثوابت وعمليات التهيئة تعتمد على ترتيب التنفيذ. التجميع يلصق محتوى الملفات كما هو، ويحافظ على التعليقات والمسافات ونهايات الأسطر.

## ملفات التشغيل الحالية

**تنبيه خاص بالإنتاج:** المراجعة البعيدة بتاريخ 8 أكتوبر 2026 وجدت أن نسخة الإنتاج 38 مختلفة عن نسخة التطوير المحلية هنا. حزمة الإنتاج التي تحافظ على الكود الفعلي موجودة في `apps-script/production/`؛ راجع دليلها قبل أي نشر على السيستم الفعلي. هذا المجلد يستمر كمصدر نسخة التطوير المحلية دون محو تعديلاتها.

`scripts/app-script-final-owner-access.js` وملفات Phase 1–5 الأصلية في `scripts/` أصبحت نواتج توافق مولدة من المصادر هنا. لا تعدّلها يدويًا؛ التعديل سيُرفض في فحص الحزمة أو يُستبدل عند التجميع.

النشر الحالي يستمر باستخدام الملفين المحددين في `config/apps-script-deployment-package.json`:

- `scripts/app-script-final-owner-access.js`
- `scripts/booking-availability-phase5-apps-script-bundle.gs`

ملفات `backend/` هي ملفات التطوير. لا ترفعها بجانب الملفين المجمّعين، لأن ذلك يكرر التعريفات. إعادة التنظيم المحلية لم تغيّر مشروع Apps Script البعيد أو التريجرات أو الشيتات أو Script Properties. نقل مشروع Apps Script نفسه إلى عدة ملفات منشورة يتطلب اختبار حزمة مختلفة وترتيب تهيئتها؛ ليس جزءًا من هذه الحزمة التي تحتفظ بطريقة النشر الحالية.

مولّد Phase 5 يقرأ المصادر الجديدة مباشرة. مولّدات المراحل السابقة تستخدم نفس المصادر، لكن حزم المراحل السابقة تظل خارج حزمة النشر الحالية.

## دليل الحفاظ على السلوك

`docs/backend-refactor-baseline.json` يسجّل بصمات SHA-256 وأحجام الملفات قبل التقسيم، وأسماء التعريفات وحدود أسطرها الأصلية. تم تحليل الملفات كاملة، والفصل عند حدود تعريفات المستوى الأعلى، دون إعادة ترتيب أو إعادة كتابة أجسام الدوال.

لإعادة إثبات التطابق مع لقطة 8 أكتوبر 2026:

```sh
node scripts/build-backend.js --check-baseline
```

هذا فحص تاريخي لهذه العملية فقط. بعد تعديل سلوك الباك إند عمدًا، اختلاف البصمة التاريخية متوقع؛ استخدم `--check` واختبارات السلوك للتحقق من التعديلات الجديدة. لا تُحدّث اللقطة التاريخية لمجرد تمرير الفحص.
